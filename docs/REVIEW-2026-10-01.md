## Summary

The engineering is well above average for a tool this young:

- The state machine is pure and has an exhaustive transition table.
- Store transactions are `BEGIN IMMEDIATE` and the store actor catches panics.
- Gates are bound to an occurrence and a subject.
- Snapshots don't follow links.
- The toast path is hardened.
- Crash-point tests exist at every stage boundary.

**Theme of the findings.** Think of the 棟梁 inspecting the joints: the inspection is thorough, but in several places the ruler it measures with belongs to the craftsman or the client. Examples:

- a commit trailer the agent can forge (H1)
- a sandbox level chosen by the repository file (H2)
- a YAML tag that hides a key from the R60 check (C1)
- a directory the scan cannot list, which the scan then treats as empty (H4)

Most of the serious findings are **fail-open checks on input the agent or the repository controls**. Each fix is local and small.

A second cluster is the **verify output pipeline**: the output is buffered without a limit, never redacted, and decoded as UTF-8 only. One `LocalRunner` rewrite fixes all three (M1, M2, M13).

**Verdict: Request changes.** Land C1 and H1–H6 before running Toryo against a repository you don't fully control, or with `codex-foundry` secrets on long D365FO builds (H5). The rest can go into M11 in normal order.

## Critical

### C1 — A YAML tag bypasses R60, so a repository `toryo.yaml` can define agent profiles ✔ (reproduced)

`src/config.rs:893-912` (check) · `:510` (typed parse) · `:535-538` (merge)

- **Defect.** `machine_only_part` looks keys up with `map.get("profiles")` on a `serde_yaml::Value`. A tagged key (`!x profiles:`) is stored as a `TaggedValue`, so the lookup misses it. The typed `RepoConfig` parse drops the tag and fills `repo.profiles` anyway.
- **Reproduced** with serde_yaml 0.9.34:
  - the raw check sees `profiles=false`
  - the typed parse returns `profiles=["evil"]`
- **Scenario.** A commit adds `!x profiles: { evil: { kind: codex, exe: 'tools\evil.exe', secret_env: { K: 'credman:toryo/foundry-openai' } } }` plus `roles: { implementer: { profile: evil } }`. The shipped machine templates override only `planner` and `reviewer`, so the repository's implementer role stands.
  - `toryo doctor` and the R51 gate run `evil.exe --version` (`evidence.rs:163-167`) at Medium IL, from the repo's working directory.
  - With `--accept-unverified`, `evil.exe` then runs as the implementer with the resolved Credential Manager secrets.
- **Fix.**
  1. Deserialize the repository file into a separate `RepoFile` struct with **no** `profiles`/`toolchains` fields and `#[serde(deny_unknown_fields)]`, then build `RepoConfig` from it.
  2. Reject any tagged top-level key.
  3. Add a `!x profiles:` regression test next to the existing R60 tests.

## High

### H1 — Crash recovery accepts an agent-forged checkpoint commit ✔

`src/engine/recovery.rs:296` · `src/engine/worktree.rs:170-186` · `src/engine/runner.rs:1096-1106`

- **Defect.** `recover_writing` runs the trailer search (`find_checkpoint`) before the HEAD-guard soft reset (`:341`). Any commit in `base..HEAD` whose `Toryo-Task` / `Toryo-Stage` / `Toryo-Attempt` trailers match is marked `Succeeded`, with `ImplementationDone`. All three values are predictable from earlier checkpoints.
- **Scenario.**
  1. A prompt-injected implementer runs `git commit --trailer "Toryo-Task: T-1" …`.
  2. The owner dies. `toryo run` installs no Ctrl+C handler, so a closed terminal or a reboot is enough.
  3. On `resume`, recovery matches the forged commit and marks the turn succeeded.
  4. `checkpoint()` then sees `found=true`, which skips the deny-path check (`runner.rs:1108-1119`) and the post-turn path policy. The agent's commit becomes the verified, reviewed checkpoint.
- **Existing test.** `regress_recovery.rs` f4 only covers an agent commit *without* trailers.
- **Fix.**
  1. Accept a trailer match only if `c.sha == HEAD` and `parent(c.sha) == a.git_head_before`.
  2. Bind the match to a write-ahead record: store the `git write-tree` id (or an intent row) in the DB *before* `git commit`, and require the found commit's tree to equal it.
  3. Treat anything else as an agent commit and soft-reset it.

### H2 — The verify sandbox level is chosen by the repository, with no machine floor ✔

`src/config.rs:164-175, 148-161` · `src/engine/verify.rs:46-52` · `src/engine/task.rs:114`

- **Defect.** `verify.boundary`, `verify_root` and `policy.allow_submodules` exist only in the repository `toryo.yaml`. `MachineConfig` (`config.rs:408-424`) has no `verify` or `policy` key, so the owner cannot pin them.
- **Scenario.** A commit sets `verify: { boundary: none }`.
  - `task create` accepts it, and implementer-written code then runs at Medium IL, with write access to the user profile and to the R51 evidence file.
  - The only signal is a `doctor` WARN.
  - A repository-chosen `verify_root` is also where toryo applies Low labels and later calls `remove_dir_all`.
  - This contradicts R60's own rationale: repository content must not choose "the sandbox they run in".
- **Fix.**
  1. Add a machine-level floor, e.g. `verify: { min_boundary: low_integrity, verify_root: … }` in `toryo.local.yaml`.
  2. When the repository asks for `none`, refuse, or require an explicit `task create --trusted-code` that is frozen with the task.

### H3 — R51 evidence is not bound to the launch mode or the profile definition ✔

`src/evidence.rs:231-258, 263-279` · `src/engine_cli.rs:227`

- **Defect.** A canary record matches on (spike, profile name, CLI version) only.
  - The Claude isolation record stores `"mode"` (`spike/agents.rs:350`), but `evidence_status` never compares it.
  - The engine always launches with `LaunchMode::Restricted`.
- **Scenario (mode).** `doctor --canaries --claude-mode setting-sources` passes, and `toryo run` then uses the Restricted launch line, which was never tested.
- **Scenario (profile).** After `codex-canary` passes, the owner changes `exe` to the npm `codex.cmd` shim (same version string), or adds `codex.overrides: { sandbox_workspace_write.writable_roots: … }`, which `denied_override` allows. The profile stays "Verified".
- **Scenario (tampering).** `results.jsonl` has no integrity protection. Any Medium-IL process can append a passing record; see H2 for how one gets to run.
- **Fix.**
  1. Store a fingerprint in each record: launch mode, a digest of the launch-line template, a hash of the isolation-relevant profile fields, the exe's SHA-256, and the toryo version.
  2. Require the fingerprint to match in `evidence_status`.
  3. The engine requires a `Restricted`-mode record specifically.
  4. Optionally sign records with an HMAC key held in Credential Manager.

### H4 — The protected-state scan treats an unreadable directory as empty (fail-open) ✔

`src/engine/protect.rs:127-130`

- **Defect.** `let Ok(rd) = std::fs::read_dir(dir) else { return Ok(()) };` and `rd.flatten()` silently drop listing errors. A directory is recorded only through the files it lists.
- **Scenario.** The agent creates `.codex/` or `.claude/` with an ACL that denies listing but allows opening a file by its path (a deny-list ACE on Windows, `-wx` on Unix).
  - The R35 scan sees nothing, and `git status` / `git add -A` only print a warning.
  - The planted config stays in place, and a later stage that opens it by path loads it.
- **Fix.**
  1. Fail closed: any `read_dir`, `file_type` or metadata error under the worktree becomes `protected_config_changed`.
  2. Record every protected directory entry itself, not only the files inside it.
  3. Add an "unreadable protected directory" test.

### H5 — With any secret configured, the redactor holds back the line-ending newline, and long D365FO builds get killed as "stalled" ✔

`src/process/redact.rs:180-184` · `src/process/mod.rs:118-140` · `src/agents/events.rs:104-125` · `src/agents/adapter.rs:102-108`

- **Defect.** `StreamRedactor` keeps the last `max_len-1` bytes of every chunk until more output arrives. When a secret is set, the `\n` that ends the latest stdout line is inside that tail, so the line is not parsed while the agent is quiet.
- **When a secret is set.**
  - The documented `codex-foundry` profile sets `AZURE_OPENAI_API_KEY`.
  - Any parent environment with `CLAUDE_CODE_OAUTH_TOKEN` also counts, because `exec.rs:132-137` always adds it.
- **Scenario.**
  1. Codex prints `item.started` for an X++ build, then stays silent until the build ends.
  2. `CommandRunning(true)` is never delivered, so the stall timer keeps counting.
  3. After `agent_stall_min` (10 min by default) the turn is killed as `Timeout`. This is exactly the EC-06 case the design says it handles.
- **Why the tests pass.** The EC-06 tests (`tests/regress_agents.rs:1076-1200`) use profiles with no secrets, so redaction is a no-op there.
- **Fix.**
  1. In `process()`, treat everything up to the last `\n` as final: `final_before = max(final_before, last_nl + 1)`. Neither a literal secret nor its JSON-escaped form can contain a raw newline; turn this shortcut off only if a configured secret value itself contains one.
  2. Add a hub test that uses `secret_env` together with a long-running command.

### H6 — The "read-only role wrote to the worktree" check (EC-31) and the R35 check are skipped when a Planner or Reviewer turn ends by quota, stop or budget ✔

`src/engine/runner.rs:1714-1719, 1821-1835` · `src/engine/recovery.rs:215-233`

- **Defect.** `cut_short` (stop/budget) and the quota branch of `after_read_only_turn` return *before* `protected_violation` and `read_only_write` run. The attempt is already `failed` or `interrupted`, so recovery doesn't re-check it either.
- **Scenario.**
  1. The Reviewer edits `src/Calculator.psm1`, then hits `QuotaExceeded`, and the task pauses.
  2. On `resume`, the next turn's `before` snapshot already contains the edit, so under F5 it is treated as the human's file.
  3. The next Implementer checkpoint (`git add -A`) commits the Reviewer's edit under the Implementer's name.
- **Fix.**
  1. Run `read_only_write`, the HEAD check and `protected_violation` right after the turn returns, before `cut_short` and before the quota branch.
  2. Persist the pre-turn `TreeState` hashes on the attempt, so recovery can make the same comparison (this also fixes M19).

## What looks good

- **State machine.** `transition(state, event)` is pure and applied to a copy, and `transition_table_is_exhaustive` pins every pair. `store::transition` persists the machine, the projections, the approvals and the event in the caller's transaction.
- **Store.** Each call is one `BEGIN IMMEDIATE` transaction. The actor catches panics and forces a ROLLBACK. It uses WAL, `synchronous=FULL` and `busy_timeout`, and read-only paths use a rolled-back deferred transaction that is proven never to wait for a writer.
- **Gates.** They are bound to an occurrence and a subject (R44a/R32) and re-checked on approve (plan hash, branch tip, verify currency). On a mismatch the gate is withdrawn, never approved silently.
- **Artifacts.** Staging with `sync_all`, publish that never overwrites, and a separate version-checked `register` step make multi-artifact atomic commits possible. The frozen config is loaded by the SHA of an immutable version.
- **Process containment.** Suspended create, then Job assignment (`KILL_ON_JOB_CLOSE`, no breakaway), then resume, with fault injection (`TORYO_FAULT_ASSIGN`). Correct Win32 struct sizes. Clean handle ownership hand-off.
- **Redaction.** `StreamRedactor` merges overlapping matches, never cuts inside a UTF-8 character, and is covered by every-split and fuzz tests. `Debug` never prints a secret value. Flight-recorder redaction fails closed through an exhaustive `fields_named` match.
- **Agent I/O.** Prompts go through stdin (no 32k command-line limit, no shell). Separate reader threads prevent pipe deadlock. A 32 MB per-line cap. Tolerant parsers. Disjoint usage buckets with reset-safe deltas, checked against both Claude fixtures.
- **Toast hardening.** A constant `-Command` script, text passed only through environment variables and inserted with `CreateTextNode`, XML-safe cleaning, `CREATE_NO_WINDOW`, and a 10 s deadline followed by a kill.
- **X++ build.** argv arrays, a BOM-prefixed response file with the trailing-backslash quote issue handled, `-noAutoResponse -nodeReuse:false`, and `Directory.Build.*`, `obj/**` and `.rnrproj.user` protected.
- **Test harness.** Per-test TempDir, `TORYO_DATA_DIR` and machine config; `wait_until` polling instead of fixed sleeps; crash injection at every stage boundary; `tests/architecture.rs` keeps vendor types out of the engine; canaries have positive and negative controls.
